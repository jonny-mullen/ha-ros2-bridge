# Changelog

All notable changes to ha-ros2-bridge are recorded here. The format follows Keep a Changelog, and the project will follow Semantic Versioning from the first tag. Dates are ISO 8601. Each release section is also the body of the GitHub release (`release.yml`).

## [Unreleased]

### 2026-10-14 (towards 0.2.0)

Joint telemetry: an additive extension of contract schema 1 so that a dashboard can show each arm's articulation (`docs/decisions.md`, revising interview decision Q17). Nothing on the wire that existed in 0.1.0 changed: a 0.1.0 Home Assistant ignores the new announce block and never subscribes to the new topic, and a 0.1.0 node never publishes either. New and on by default: a node whose executor announces joints (the fake always, the MoveIt executor when `moveit.joint_names` or the first pose names them) publishes the joints topic at `telemetry.joints_rate_hz` 2.0 from its first start after the upgrade, and Home Assistant creates one recorded sensor per joint; `docs/upgrading.md`, 0.2.0, gives the two ways to keep 0.1.0 behaviour. Not yet exercised on a live broker or opened on a live Home Assistant; no tag yet.

#### Added

- Contract: the optional `joints` block in `announce` (`unit` deg or rad, 1 to 32 `names`, `limits` null or one pair per name, `rate_hz`), the `{prefix}/{robot_id}/joints` payload (QoS 0, never retained, MQTT 5 message expiry 5 s; `positions`, `velocities`, `session`, `instance`, `seq`, `ts`), `contract/schemas/joints.schema.json`, the shared definitions, golden and must-reject examples, and the vendored copies in the ROS 2 package.
- ROS 2 node: the parameters `telemetry.joints_rate_hz` (default 2.0; 0 disables publishing and the announce omits `joints`) and `telemetry.joints_min_delta` (default 0, meaning the unit's own default: 0.5 for degrees, 0.01 for radians); `TaskExecutor.joints()` returning a frozen `JointInfo` (names, unit, limits) or `None`, called once after `setup`; the thread-safe `BridgeContext.report_joints(positions, velocities=None)`; the node throttles to the rate, publishes on change only plus once on every (re)connect and announce, and numbers each publication with `seq` within the session.
- Fake executor: seven joints `j1` to `j7` in degrees, limits -170 to 170 except `j4` and `j6` at -120 to 120, the named poses home, pick, place and wave; `reset` and `move_to` interpolate linearly from the current positions over `fake.task_duration_s` with a report every `1/fake.feedback_hz` seconds, `wait` holds, `fail` moves halfway and aborts, `pause` freezes and `resume` continues; positions persist across tasks and the unknown-pose rejection stays.
- MoveIt executor: the adapter subscribes to `sensor_msgs/JointState` on `moveit.joint_states_topic` (default `/joint_states`) and forwards the positions of the group's joints, named from the first poses entry or `moveit.joint_names`, in radians with no limits; the node throttles.
- Home Assistant: a subscription to `{prefix}/+/joints` at QoS 0 (eight filters in all); one sensor per announced joint (unique id `{robot_id}_joint_{index}`, name "Joint {index + 1} {joint name}", unit ° or rad, display precision 1 for degrees and 3 for radians, no state class, attributes `index`, `joint_name`, `limit_min`, `limit_max`, enabled by default), unavailable with the robot, removed when a later announce drops the joint or the key; `seq` regressions within a session are dropped; diagnostics show the latest positions and the joints `seq`.
- `docs/examples/dashboard.yaml` and `docs/dashboard.md`: a phone-first Lovelace dashboard for the two fake arms (an Overview with the state, the task buttons and the last result per arm, and one view per arm with its status, seven gauges with the announced limits, the task and pose buttons, a 30-minute history graph and the task-result logbook), native cards only, with a leading comment on installing it and adapting it to other robots.
- Documentation: the joints path and the recorder exclude (`entity_globs: sensor.*_joint_*`) in `docs/sensors.md`; the joint sensors and the recorder note in `docs/install-ha.md`; the new payloads in `docs/mqtt-contract.md` and `contract/README.md`; the feature and the new pages in `README.md`.
- Tunables audit, same day, ROS 2 node: the parameters `mqtt.takeover_suspect_s` (10.0; the window after a successful connect in which a broker-sent DISCONNECT with any reason code counts as a session takeover, 0 leaves reason code 142 as the only signal), `mqtt.takeover_window_s` (600.0), `mqtt.offline_wait_s` (2.0; the wait for the retained offline to be acknowledged at a clean stop), `mirror.ros_queue_depth` (10), `watchdog.ros_topic` (`~/ha_link`), `logging.warn_interval_s` (10.0; the spacing of the rate-limited warnings, 0 warns on every event), `command.dedupe_write_interval_s` (1.0; 0 rewrites `dedupe.json` at every accepted ack), `moveit.joint_tolerance_rad` (0.01), `moveit.motion_timeout_s` (120.0) and `moveit.control_timeout_s` (5.0), each with its former constant as the default; the launch arguments `namespace`, `respawn`, `respawn_delay` and `respawn_max_retries` on `bridge.launch.py`, and the same keys per robot in the fleet file.
- Tunables audit, same day, Docker rig: `ROS2_HA_BRIDGE_PARAM_<NAME>` sets any node parameter from the environment (the dotted name upper-cased with each dot as a double underscore, typed from the node's parameter table; the two secrets are refused by name and an unknown name fails the render), next to the existing `ROS2_HA_BRIDGE_PARAMS_FILE` mount; commented `volumes:` entries for a parameters file and for `data_dir` in `compose.yaml`; `RMW_IMPLEMENTATION` and `ROS_AUTOMATIC_DISCOVERY_RANGE` overridable from `.env`.
- Tunables audit, same day, Home Assistant: the options `ack_expiry_s` and `result_expiry_s` (must equal the node's `reply.ack_expiry_s` and `reply.result_expiry_s`), `replay_settle_s`, `session_change_grace_s`, `feedback_throttle_ms`, `heartbeat_stale_intervals`, `clock_skew_warn_ms`, `duplicate_session_changes`, `duplicate_session_window_s`, `duplicate_quiet_s`, `mirror_extra_attributes` (names appended to the sensor mirror's attribute allowlist) and `intent_ack_wait_s`, defaults unchanged, in an Advanced section of the options form; the joint sensors' `velocity` (the reported velocity in the announced unit per second, null when the robot reports none) and `moving` attributes.

## [0.1.0] - 2026-10-14

The first release: a Home Assistant custom integration (`custom_components/ros2_bridge`, installable through HACS as a custom repository) and a ROS 2 Jazzy package (`ros2/ros2_ha_bridge`), joined by the MQTT contract under `contract/`. Home Assistant sends named tasks to robots and sees their state and results; ROS 2 runs the tasks through an executor plugin and owns safety. Requirements: Home Assistant 2026.10.0 or newer with the MQTT integration on an MQTT 5 broker, ROS 2 Jazzy on Ubuntu 24.04, paho-mqtt 2.1.0 from pip.

Verified for this release:

- `colcon test` inside `ros:jazzy-ros-base`: 983 tests, 0 failures. The rclpy-free core suite: 932 tests on plain Python.
- The Home Assistant suite: 506 tests, 96 percent coverage, hassfest and the HACS validation green in CI.
- The live end-to-end checklist (`tools/e2e_checklist.md`) run on 2026-10-14 against Home Assistant 2026.10.1 with the Mosquitto add-on 7.1.1 and two fake arms in Docker: steps 1 to 13 pass, including watchdog modes, a Home Assistant restart mid-task, a duplicate robot id, device deletion and the voice path through Assist.
- Measured latency (`docs/architecture.md`): command to retained ack median 49 ms, p95 59 ms, through the broker and back.

Defects found on the live run and fixed before this tag: the intent platform hook name and an import inside the event loop; the ROS log handler and rclpy's one-severity-per-call-site rule; takeover detection on Mosquitto 2.1, which evicts a duplicated client id with reason code 0 rather than 142; the last-result sensor lost on an options reload; and the Assist slot `name`, which Home Assistant resolves as an entity name (now `robot`).

Known limitations: the MoveIt 2 executor is experimental (unit-tested with a fake adapter, never run against a real `move_group`; `docs/simulator_checklist.md` is the procedure for the Isaac site); signed commands (HMAC) are tested in both suites but have not been exercised on a live broker; a topic-prefix change and the node-side `mirror.topics` subscription are covered by unit tests only; the voice check used Home Assistant's conversation service rather than a Voice PE; the stock Mosquitto add-on's missing ACL enforcement is reported from an open issue, not reproduced; one motion task runs at a time per robot (`rejected_busy`, no queue); a changed task catalogue needs a node restart.
